# TLS certificate for the gateway — dev only

`server.crt`/`server.key` in this directory (generated by `generate-dev-cert.sh`, not
committed as static files by default — run the script to produce them) are a
**self-signed certificate for local development only.**

- It is not signed by any trusted CA. No mobile OS, browser, or standard HTTP
  client will trust it out of the box. Local dev/testing works around this by
  either disabling certificate verification client-side (see
  `farmiq_mobile_api_documentation.md` and `envoy/smoke-test.py` for exactly
  where this is done, and the warnings attached to it) or installing this
  specific cert as a trusted dev cert on a simulator/device.
- **Never do either of those things against a real deployment.** Disabling
  certificate verification or trusting an ad-hoc dev cert defeats the point of
  TLS — it protects against nothing once that's done.
- **Before any real deployment:** replace `server.crt`/`server.key` with a
  certificate from a real CA (e.g. Let's Encrypt for a public domain, or your
  organization's internal CA) issued for the gateway's actual hostname — not
  `localhost`. `envoy/envoy.yaml`'s `tls_certificate` block just needs to point
  at the new files; nothing else about the gateway config changes.
- Regenerate the dev cert any time with `./generate-dev-cert.sh` — it's a
  365-day cert, so this will need to happen at least yearly even for local dev.
